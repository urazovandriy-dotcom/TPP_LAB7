# Лабораторна робота №7: Обробка виняткових ситуацій та модульне тестування в C++20

## Варіант 14: Аналіз тексту

Даний проєкт є розвитком бібліотеки аналізу та порівняння текстових файлів. У межах роботи реалізовано повноцінний клас зі станом `TextAnalyzer`, власну ієрархію типізованих винятків, забезпечення сильної гарантії безпеки (Strong Exception Guarantee), демонстрацію розкручування стека (Stack Unwinding) через `ScopeLogger` та набір модульних тестів на базі Google Test.

## 2. Ієрархія винятків та сценарії помилок

Усі користувацькі винятки бібліотеки успадковані від базового класу TextAnalyzerException (який походить від std::runtime_error) або відповідних стандартних класів std::exception:

1. FileNotFoundException (TextAnalyzerException):
   - Викидається при спробі відкрити файл, якого немає на диску.
   - Зберігає та повертає діагностичний шлях через метод getFilePath().
2. FileReadException (TextAnalyzerException):
   - Викидається у разі відсутності прав доступу, блокування файлу іншим процесом або помилки читання потоку (badbit).
3. EmptyWordSetException (TextAnalyzerException):
   - Викидається при спробі вибірки найчастіших слів (getTopWords) у порожньому або неініціалізованому документі.
4. InvalidTopNException (TextAnalyzerException):
   - Викидається, якщо запитане число N у методі getTopWords(n) є непозитивним (N <= 0) або перевищує загальну кількість унікальних слів.
   - Зберігає запитане значення N та фактичну кількість унікальних слів.
5. InvalidSearchQueryException (std::invalid_argument):
   - Викидається при передачі порожнього рядка або рядка без літер/цифр у метод getWordFrequency.

## 3. Гарантії безпеки винятків

Strong Exception Guarantee (Сильна гарантія):
  - Реалізована в методі TextAnalyzer::loadFile(path) та в операторі присвоєння.
  - Усі операції зчитування, розбору рядків та підрахунку частот слів спочатку виконуються у локальних тимчасових змінних (tempLines, tempFreq, tempUnique).
  - Лише після успішного завершення всіх потенційно аварійних дій внутрішній стан класу оновлюється за допомогою операцій переміщення std::move (без генерації винятків).
  - Якщо під час зчитування файлу виникає збій, стан об'єкта залишається ідентичним до моменту виклику.

No-throw Guarantee (noexcept):
  - Конструктор за замовчуванням, деструктор, переміщувальні операції, метод swap(), а також геттери стану позначені як noexcept.

## 5. Інструкція зі збірки та запуску

### Варіант А: Через Visual Studio 2022
1. Відкрийте папку репозиторію через меню Файл -> Відкрити -> Папку.
2. Зачекайте завершення автоматичної конфігурації CMake (з'явиться напис CMake generation finished).
3. Виконайте збірку всього рішення (Ctrl + Shift + B).
4. Для запуску відповідного модуля виберіть його у випадаючому списку запускаємих елементів:
   - main_demo.exe — демонстрація розкручування стека та сильної гарантії.
   - bad_exceptions.exe — демонстрація наслідків використання винятків нерекомендованих типів.
   - unit_tests.exe — запуск модульних тестів Google Test.

### Варіант Б: Через командний рядок (CMake CLI)
1. `cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE="%VCPKG_ROOT%/scripts/buildsystems/vcpkg.cmake`
2. `cmake --build build --config Debug`
3. `ctest --test-dir build -C Debug --output-on-failure`

## 6. Результати виконання та тестування

1. main_demo: продемонстровано розкручування стека через деструктори ScopeLogger у зворотному порядку (LIFO), перехоплення винятку з повторним генеруванням (throw;) на проміжному рівні та незмінність стану об'єкта TextAnalyzer після виникнення помилки завантаження.
2. bad_exceptions: продемонстровано, що генерація примітивних типів (int) та сирих рядків (std::string) не перехоплюється блоком catch (const std::exception&), а вимагає блоку catch (...), що призводить до втрати контексту помилки.
3. unit_tests: реалізовано 7 тестових сценаріїв Google Test, які покривають успішний аналіз, перевірку винятків через EXPECT_THROW та верифікацію сильної гарантії[cite: 7, 9]. Усі тести успішно пройдені.
4. Негативний самоконтроль: проведено контрольне внесення навмисної помилки у валідацію пошукового запиту, зафіксовано падіння відповідного тесту (Actual: it throws nothing) та відновлено працездатність.
